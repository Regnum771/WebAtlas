## How K2 works (for whoever continues)

- **Cascade layers:** `theme, base, legacy-compat, legacy, components, utilities`, declared in `apps/web/src/styles/app.css`. Every legacy stylesheet is imported there into `legacy`, and no `.ts`/`.tsx` file may import CSS (a test enforces this). The minifier drops the `@layer` statement, so the build's layer order comes from first appearance: `legacy-compat.css` must be imported before the legacy files.
- **`legacy-compat.css`** mirrors all of Tailwind's preflight with `revert`, for legacy elements only. It excludes `[data-slot]` primitives, except dialog parts, so legacy content inside dialogs keeps browser defaults. Because a `revert` there also beats anything in `base`, never add a compat rule for a property the R9 focus rule sets.
- **Tailwind scans only listed folders** (`@source` in `app.css`), never their tests. Each sub-project adds the folders it converts and checks that no legacy class token in them matches a generated utility.
- **Primitives** live in `src/shared/ui`, built on `src/shared/ui/shadcn/*`. The export names are unchanged. Dialogs are Radix (`useReturnFocus` returns focus to the opener, since there is no Trigger). ConfirmDialog is an AlertDialog: an outside press does nothing.
- **Toasts:** `toast.store` keeps the policy; Sonner only draws. Sonner's injected CSS is unlayered, and only inline styles beat it. Each toast's list item is taken out of the tab order, and focus events inside a toast are kept from Sonner's refocus logic.
- **The shadcn CLI** resolves our `utils` alias to an npm package called `cn`, and installs it, on every `add`. After each `add`: uninstall it, and point imports at `@/shared/lib/utils`. `shadcn.test` fails otherwise. The CLI also stops at "overwrite?" prompts for files we already own. Answer `n`, one component at a time.

## Decisions made on the user's behalf during K2

Each was recorded at the time with its cost if wrong; all are in the code now.

- The compat sheet has its own layer below `legacy`, and mirrors all of preflight.
- Dialog containers don't count as primitive scopes for the compat sheet.
- Legacy contextual styling: `.btn.on-green` became `Button variant="inverse"`. AttributeField's unit moved to a new `TextField` `after` slot.
- Inputs use an `ink-2` border (WCAG 1.4.11), and outline buttons a `line` border.
- No `baseUrl` in the tsconfigs (TS 6 deprecates it); `paths` alone.
- The dialog content sits inside a flex-centred overlay, with 14 px padding (as before).
- ConfirmDialog queries in tests use `alertdialog`. One presenter test uses `fireEvent` with `hidden: true` behind a modal. One test opens two modals in two renders, as the app does.
- Sonner's section has an empty label (no new landmark). The test setup stubs pointer capture.
- The legacy comparison leaves out width, height and offsets, because the primitives were meant to change size. `.top-bar-search`'s auto-margin shift is accepted.

## Deferred minors (not blocking; pick up when touching the area)

**Legacy style script**
- `--compare` can snapshot a page before late elements render; rerun on a small missing-element difference.
- Its 50-line output can hide the cause; print added and missing lines first.
- Class names containing `.` (for example `w-1.5`) split ambiguously in element keys.
- It doesn't cover pseudo-elements, hover/focus states, other widths, dialogs or toasts.

**Cascade test**
- It checks only three at-rules before the imports.
- The CSS-import pattern misses `import(/* c */ './a.css')` and `import.meta.glob`.

**Dialogs**
- Two Radix modals mounted open in the same commit leave the later one hidden from assistive technology. The app never does this today.
- The overlay and content class strings are duplicated in `shadcn/dialog.tsx` and `shadcn/alert-dialog.tsx`.
- No test pins `onCancel` being called exactly once on a Huỷ click.
- `useReturnFocus`: an `autoFocus` child in a dialog mounted open is recorded as the opener, and an opener unmounted by close time leaves focus on body.

**Toasts**
- Swipe-down dismisses sticky errors; pass `dismissible: false` to stop it.
- The `MAX_TOASTS` test doesn't exercise the store-to-Sonner dismiss at DOM level.
- The replaced-action test depends on timer order.
- There are three nested live regions, so some screen readers may announce an error twice.
- If the store and Sonner ever disagree, a toast's own buttons can't remove it.

**Look**
- The R9 rule sits in `base`, so any legacy `box-shadow` or `outline` declaration beats it. K3 meets this on converted screens.
- 32 px TextFields sit beside 34 px legacy `.input` selects in five forms until those screens convert.

**Test flakes under load**
- `copy.test`, `personalLayers.test`.
